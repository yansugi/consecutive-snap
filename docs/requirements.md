# ConsecutiveSnap 要件定義書 (v0.2 ドラフト)

## 1. 概要
指定した画面範囲を、「撮影 → 操作シーケンス → 撮影 → …」の順で指定回数だけ繰り返し、
スクリーンショットを連番ファイルとして保存する Windows デスクトップアプリ。
電子書籍ビューア・PDF・スライド・Web ページなど、ページをめくりながら同じ範囲を撮り続ける用途を想定する。

## 2. 技術スタック・対象環境
- 対象OS: Windows 10/11（x64）
- 技術: .NET 8 / WPF（C#）。SnipSnap と同一構成
- 外部NuGetパッケージは原則使わない（サプライチェーン攻撃面の最小化）。
  画面キャプチャ・入力送信・キー監視はすべて OS 標準 API（GDI / user32.dll）で実現する
- 外部ネットワーク通信・外部API呼び出しは一切行わない
- 配布形態: exe（自己完結型の単一ファイルを想定。SnipSnap の dist と同様）

## 3. 用語
| 用語 | 意味 |
|---|---|
| キャプチャ範囲 | ユーザーが指定した矩形（スクリーン物理ピクセル座標） |
| 操作シーケンス | 撮影と撮影の間に実行する、事前に指定したステップの並び |
| ステップ | シーケンスの1要素（キー入力 / マウスクリック / 待機） |
| 繰り返し回数 | 撮影する回数（= 保存される画像の枚数） |

## 4. 機能要件

### 4.1 範囲指定（SnipSnap 方式を踏襲）
- 「範囲を指定」ボタンで、全モニターの静止画を背景にした全画面オーバーレイを表示する
- ドラッグで矩形を選択し、マウスを離すと確定。Esc でキャンセル
- マルチモニター・モニターごとに異なる DPI に対応する（モニター1台につき1オーバーレイ）
- 確定した範囲は座標・サイズを画面に表示し、設定として保存して次回起動時に復元する
- 範囲は何度でも指定し直せる

### 4.2 撮影
- 指定範囲を `Graphics.CopyFromScreen` で撮影し PNG で保存する
- 撮影時に本アプリのウィンドウ・オーバーレイ・カウントダウン表示が写り込まないようにする
  （実行開始時にメインウィンドウを最小化し、進捗表示は撮影範囲の外に置く）
- マウスカーソルは写さない

### 4.3 操作シーケンス（撮影の合間に実行）
撮影と撮影の間に、事前に登録したステップを**上から順に**実行する。ステップは複数登録でき、追加・削除・並べ替え・編集ができる。

| ステップ種別 | 内容 |
|---|---|
| キー入力 | 単独キー（→ / ← / ↓ / PageDown / Space / Enter 等）または修飾キー付き組み合わせ（Ctrl+→ 等）。キー入力欄で実際にキーを押して指定する |
| マウスクリック | 指定したスクリーン座標を左クリック。座標は画面上をクリックして指定する |
| マウスホイール | 上／下方向へ指定ノッチ数（1〜100）回す。任意で位置を指定でき、指定した場合はその座標へカーソルを動かしてから回す（ホイールはカーソル下のウィンドウに届くため）。指定しなければ、その時点のカーソル位置で回す |
| 待機 | 指定ミリ秒だけ待つ |

- 例: 「キー: → ／ 待機: 300ms ／ クリック: (1200, 800) ／ 待機: 500ms」
- 送信は `SendInput` で行う
- マウスクリック後にカーソルを元の位置へ戻すかどうかを設定可能にする
- ステップ間の待機は明示的に「待機」ステップとして置く。**最後のステップの後には、ページ描画待ちとして「操作後待機」（既定 500ms）を自動で挿入**してから次の撮影を行う
- シーケンスは設定に保存し、次回起動時に復元する
- 最終回（N 枚目）の撮影後はシーケンスを実行しない

### 4.4 実行制御
| 設定項目 | 内容 | 既定値（案） |
|---|---|---|
| 繰り返し回数 | 撮影回数。1〜9999 | 10 |
| 開始前の待機時間 | 開始ボタンから最初の撮影までの秒数。この間に対象アプリへフォーカスを移す | 5 秒 |
| 操作後待機 | シーケンス完了から次の撮影までの待ち（ページ描画待ち） | 500 ms |

- 開始前はカウントダウンを表示する（撮影範囲外に小さく表示）
- 実行中は進捗（n / 繰り返し回数）を表示する
- 終了は**繰り返し回数に到達したときのみ**。同一画像による自動停止は行わない
- **緊急停止: `Pause/Break` キー**（単独押し。確定）。実行中いつでも押すと即座に中断する（固定。変更UIはv1では設けない）
  - `Ctrl+Esc` は Windows のスタートメニュー用ショートカットで登録しにくいため、採用しない
  - Pause/Break キーが無いキーボード（一部のノートPC等）では緊急停止キーが使えない。その場合は Fn との組み合わせで割り当てられていることが多い。使えないキーボードでは実行前に注意を表示する
  - `RegisterHotKey` によるグローバルホットキーとして、**実行開始時に登録し、停止・完了時に必ず解除**する
  - 他アプリが同じキーを登録済みで登録に失敗した場合は、開始せずにエラー表示する（停止手段が無い状態で実行しない）
  - 補助として、メインウィンドウの「停止」ボタンも用意する（最小化中は使えないため、あくまで補助）
- 中断時、それまでに保存した画像は残す。中断・完了時はメインウィンドウを復帰して結果を表示する

### 4.5 保存
- 「保存先の親フォルダ」と「フォルダ名」を指定する。
  実行開始時に `親フォルダ\フォルダ名\` を**新規作成**し、その中に画像を連番で保存する
  （親フォルダの既定: `%USERPROFILE%\Pictures\ConsecutiveSnap\`）
- ファイル名は連番のみ（例: `01.png`, `02.png`, …）。
  **桁数は繰り返し回数に応じて0埋め**する（繰り返し回数の桁数に合わせる）
  | 繰り返し回数 | 桁数 | 例 |
  |---|---|---|
  | 1〜9 | 1 | `1.png` |
  | 10〜99 | 2 | `01.png` 〜 `50.png` |
  | 100〜999 | 3 | `001.png` 〜 `120.png` |
  | 1000〜9999 | 4 | `0001.png` 〜 |
- 連番は 1 から開始する
- 同名フォルダが既に存在する場合は、**別名で自動作成**する。`MyBook` が存在すれば `MyBook_2`、それも存在すれば `MyBook_3` …と、空いている最小の番号を使う（既存フォルダには一切書き込まない）。実際に作成したフォルダ名は、開始時と完了時に画面へ表示する
- フォルダ名に Windows で使えない文字（`\ / : * ? " < > |` 等）が含まれる場合は、入力時に検証してエラー表示する
- 保存失敗（ディスク満杯・権限なし等）時は処理を中断してエラー表示する
- 保存形式は PNG のみ

### 4.6 設定の永続化
- キャプチャ範囲・操作シーケンス・各待機時間・繰り返し回数・保存先の親フォルダ・フォルダ名を JSON で保存し、次回起動時に復元する
- 保存場所: `%APPDATA%\ConsecutiveSnap\settings.json`
- 設定ファイルが壊れていた場合は既定値で起動し、利用者に通知する

## 5. 画面構成
メインウィンドウ1枚（常駐やトレイは不要）。

```
┌ ConsecutiveSnap ─────────────────────────┐
│ [範囲を指定]  X:100 Y:80  W:900 H:1200     │
│                                            │
│ 操作シーケンス（撮影の合間に実行）            │
│  1. キー   →              [編集][削除][↑][↓] │
│  2. 待機   300 ms                           │
│  3. クリック (1200, 800)                    │
│  [＋キー] [＋クリック] [＋待機]               │
│ 操作後待機: [500] ms                        │
│                                            │
│ 繰り返し回数: [50]   開始前待機: [5] 秒       │
│ 保存先: [C:\...\ConsecutiveSnap] [参照]      │
│ フォルダ名: [MyBook]    → 01.png 〜 50.png   │
│                                            │
│ [ 開始 ]  [ 停止 ]  進捗: 12 / 50  (緊急停止: Pause/Break) │
└────────────────────────────────────────────┘
```

## 6. 処理フロー
```
開始ボタン
 └─ 入力検証（範囲・フォルダ名・繰り返し回数・シーケンス）
     └─ 保存フォルダを新規作成（既存なら MyBook_2, _3 … で別名作成）
         └─ 緊急停止ホットキー登録（失敗なら開始しない） → 本ウィンドウを最小化 → 開始前カウントダウン
             └─ i = 1 〜 繰り返し回数
                 ├─ 範囲を撮影して i 番を保存
                 ├─ （i が最終回でなければ）操作シーケンスを順に実行 → 操作後待機
                 └─ 停止要求があれば即座に中断
             └─ ホットキー解除 → 本ウィンドウを復帰 → 完了/中断を通知
```

## 7. 非機能要件
- **撮影の安定性**: 撮影・操作は UI スレッドをブロックせず、`CancellationToken` で中断を伝播する
- **エラーハンドリング**: 撮影・保存・入力送信・フック登録の各処理で例外を握りつぶさず、ログと画面メッセージで利用者に伝える
- **ログ**: 実行ごとの簡易ログ（開始時刻・枚数・失敗理由）を `%APPDATA%\ConsecutiveSnap\logs\` に出力
- **安全性**: 入力送信は実行中のみ。停止後は一切送信しない。多重起動・同時実行は禁止
- **性能**: 1枚あたりの撮影・保存は 200 ms 以内を目安（範囲 1920×1080 程度）

## 8. スコープ外（v1 では扱わない）
- 注釈編集・画像加工（SnipSnap の役割）
- 動画録画
- 同一画像検出による自動終了（今回不要と確定）
- PDF への結合出力、OCR
- 複数範囲の同時撮影
- 一時停止・再開
- 緊急停止キーの変更
- PNG 以外の保存形式
- UAC 昇格アプリ（管理者権限で動作するウィンドウ）への入力送信

## 9. 既知のリスク・留意点
- **フルスクリーン排他モード/DRM保護された画面**（一部の電子書籍・動画アプリ）は `CopyFromScreen` で黒く写る場合がある
- 対象アプリがフォーカスを持っていない場合、キー送信は別のウィンドウに入る。開始前待機でフォーカスを合わせる運用とし、実行中のフォーカス喪失は検知できない場合がある
- 緊急停止の `Pause/Break` が操作シーケンスで送るキーと重ならないようにする（シーケンスに Pause/Break が登録された場合は警告または登録を拒否する）
- 高 DPI・複数モニター混在時の座標ずれは、SnipSnap のビットマップ座標系による変換実装を流用して防ぐ
